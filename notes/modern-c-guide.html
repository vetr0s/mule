Modern C, read through this repo

The code in this repo is C23. Most of what makes it look unfamiliar is not new syntax. It is a handful of habits. Strings carry their length. A zeroed struct is always a valid object. Every function that can fail says so in its return type. Arithmetic that can overflow is checked. The compiler is set up to reject anything sloppy. C23 adds a few keywords that make those habits cheaper to write. Each section below shows the version you would have written at university, the version in this repo, and the reason for the change. The last section gives exercises to do in this codebase.

Which C you are writing

The Makefile passes -std=c23. That flag decides which keywords exist and how some old syntax is read. University courses tend to teach C89 with a few C99 additions. That is why declarations at the top of every function and #define TRUE 1 feel normal.

StandardWhat it added that you will see here
C89Prototypes, const, void *. The baseline most courses teach.
C99Declarations anywhere, // comments, designated initialisers, compound literals, va_copy, snprintf.
C11_Static_assert, _Generic, threads, atomics.
C17Defect fixes only.
C23bool and nullptr as keywords, = {}, [[attributes]], <stdckdint.h>, typeof, constexpr, auto.

Designated initialisers and compound literals are C99. They are 27 years old. They only look modern because courses skip them.

Keywords that replaced headers

/* University */
#include <stdbool.h>      /* or: #define TRUE 1 */
#include <stdlib.h>
if (p == NULL) return false;

/* This repo, src/str/str.c */
if (p == nullptr) return false;

In C23, bool, true and false are keywords. <stdbool.h> is no longer needed. That is why src/str/str.h uses bool without including anything for it.

nullptr replaces NULL. NULL is a macro that may expand to plain 0. Passed through ... to a variadic function, a 0 is an int, not a pointer. On a 64-bit target that is the wrong size. nullptr has its own type, nullptr_t, and is always a null pointer.

static_assert, alignas, alignof and thread_local also became keywords. Their C11 spellings with a leading underscore still work.

Zero is a valid state

This is the most important design idea in src/str/str.h. A Str that is all zero bytes is a real, empty string. It owns no memory. Every function accepts it.

/* University */
Str *s = str_new();          /* mallocs the struct and a buffer */
if (s == NULL) { ... }
...
str_destroy(s);
s = NULL;                    /* easy to forget */

/* This repo, main.c */
Str s = {};                  /* valid, owns nothing, cannot fail */
...
str_free(&s);                /* s is zero again, so a second free is harmless */

Three things follow from this. The struct lives on the stack, so there is one fewer allocation to fail and one fewer pointer to leak. Declaring a string cannot fail, so the only failure points are the calls that grow it. str_free resets the struct to zero, so a double free becomes a no-op instead of heap corruption.

Look at str_grow_ in src/str/str.c. realloc(nullptr, n) behaves like malloc(n). A zeroed Str therefore needs no special first-allocation path.

Initialisers and compound literals

/* University */
Str s;
memset(&s, 0, sizeof s);
StrView v;
v.data = "abc";
v.len  = 3;

/* This repo */
Str s = {};                                   /* C23 empty initialiser */
*s = (Str){};                                 /* reset through a pointer */
return (StrView){ .data = cstr, .len = n };   /* build and return in one step */

= {} zeroes every member. It is C23. = {0} does the same in C99. It reads as "set the first member to 0", and the rest are zeroed only as a side rule. The empty form says what it means. memset to zero happens to produce null pointers and 0.0 on every machine you will use, but the standard does not promise it.

(Str){} is a compound literal. It is an unnamed object of type Str. Assigning one through a pointer resets every field in one statement. When you later add a field, the reset still covers it.

Designated initialisers like .len = n name the field they set. Reordering the struct cannot silently swap two values. Fields you leave out are zeroed.

Strings that know their length

/* University */
char *s = malloc(strlen(a) + strlen(b) + 1);
strcpy(s, a);
strcat(s, b);      /* walks a again to find the end */

/* This repo */
Str s = {};
if (!str_append(&s, a) || !str_append(&s, b)) { ... }
printf("%.*s\n", STR_FMT(s));

A char * does not know its length. Every strlen and strcat scans for the terminator. A missing terminator turns into a read past the end. Str and StrView carry len next to the pointer. Length is O(1). Embedded zero bytes are allowed. A view of part of a string needs no copy.

Str still keeps a terminator after the content. That lets str_cstr hand the buffer to C APIs like fopen without copying. len is the source of truth. The terminator is there for compatibility.

printf("%.*s", len, ptr) prints exactly len bytes. The * takes the precision from the argument list. STR_FMT expands to those two arguments.

SV("abc") uses sizeof on the literal. A string literal is an array, so sizeof gives its size including the terminator. The length is computed at compile time.

Pitfall SV(p) with a char *p compiles. It gives sizeof(char *) - 1, which is 7 on a 64-bit machine. Exercise 1 fixes this.

Owners and borrowers

C has no ownership in the type system. This repo encodes it in the type names. A Str owns its buffer and must be freed. A StrView borrows bytes owned by something else. It is never freed.

A borrow has a lifetime. str_view(&s) points into s.data. Any call that can reallocate s may move that buffer. The view then dangles. The doc comment on str_view says so. Rust's borrow checker enforces this rule at compile time. In C you hold it in your head, and AddressSanitizer catches you when you slip.

Function signatures carry the same information. const Str * means the function reads and does not modify. Str * means it may modify or reallocate. A StrView passed by value means the function only reads the bytes.

Errors in the return type

/* University */
char *s = malloc(n);
strcpy(s, src);              /* crashes if malloc failed */

/* or */
if (s == NULL) { printf("error\n"); exit(1); }

/* This repo */
[[nodiscard]] bool str_append(Str *s, StrView v);

if (!str_append(&s, v)) { /* caller decides what failure means */ }

Every function that can allocate returns bool. The result goes through an out-parameter. A library never calls exit. The program decides what an error means, and a library cannot know that.

[[nodiscard]] is a C23 attribute. Ignoring the return value becomes a compiler warning. If you really mean to ignore it, write (void)str_push(&s, 'x');. That cast tells the compiler and the reader that the value was dropped on purpose.

The header also promises that on failure the string is left unchanged. This is the strong guarantee. str_grow_ keeps it by writing realloc's result to a temporary first. It only touches s once every step has succeeded. A caller can retry or carry on with the old contents.

Growing a buffer correctly

/* University */
buf = realloc(buf, size + 1);    /* on failure: buf is NULL, old block leaked */
size += 1;                       /* grows by one each time: O(n^2) total copying */

/* This repo, str_grow_ */
size_t cap = s->capacity ? s->capacity : 15;
while (cap < needed) {
    if (ckd_mul(&cap, cap, 2)) { cap = needed; break; }
}
char *p = realloc(s->data, bytes);
if (p == nullptr) return false;  /* s->data still valid */

Assigning realloc straight back to the same pointer is the most common memory bug in student C. When realloc fails it returns null and leaves the old block alive. The old pointer is now overwritten and the block leaks.

Doubling the capacity makes appends amortised O(1). Growing by a fixed amount copies the whole buffer on every step. In the worst case, a 1000-byte string grown one byte at a time copies about 500,000 bytes. With doubling it copies under 2,000.

Notice there is no cast on realloc. In C a void * converts to any object pointer implicitly. The cast is a C++ habit and only adds noise.

Checked arithmetic

/* University */
size_t bytes = cap + 1;              /* wraps to 0 if cap == SIZE_MAX */

/* Careful C99 */
if (cap > SIZE_MAX - 1) return false;
size_t bytes = cap + 1;

/* This repo, C23 <stdckdint.h> */
size_t bytes;
if (ckd_add(&bytes, cap, 1)) return false;

ckd_add, ckd_sub and ckd_mul compute the exact result and return true if it did not fit. The result lands in the first argument. These are the checks you would write by hand, except they are correct for every type combination, and you cannot get the inequality backwards.

Unsigned overflow wraps silently. Signed overflow is undefined behaviour. Either way, a size that wraps to a small number produces a small allocation followed by a large write. That is a classic heap overflow.

Aliasing and memmove

str_append(&s, str_view(&s)) appends a string to itself. The view points into the buffer that is about to be reallocated. str_append handles it in two steps. It records the view's offset before growing. After growing it rebuilds the pointer from the new buffer. The copy then uses memmove, which is defined for overlapping ranges. memcpy is not.

All of that only matters when the buffer grows. If the bytes already fit, nothing moves and the view stays valid. str_append checks for that first and skips the offset bookkeeping, the overflow check and the call to str_grow_. That fast path made a 16-byte append into a reserved buffer 62% faster. It now costs 0.72 ns against 0.51 ns for a bare memcpy. make bench measures it.

A gray area worth knowing The aliasing check compares v.data against s->data with >= and <=. The standard only defines ordering comparisons between pointers into the same object. When the view points elsewhere, the comparison is technically undefined. It works on every flat-memory machine. Converting both to uintptr_t first makes it implementation-defined instead. Real C code has many such spots. Knowing where they are is part of writing C well.

Formatting into a buffer

/* University */
char buf[256];
sprintf(buf, fmt, ...);          /* overflows on long input */

/* This repo, str_appendf */
va_copy(ap2, ap);
int n = vsnprintf(end, room, fmt, ap);          /* try the spare capacity */
bool ok = n >= 0 && (size_t)n < room;
if (!ok) {
    if (end != nullptr) *end = '\0';            /* undo the partial write */
    if (n >= 0 && str_reserve(s, (size_t)n)) {
        vsnprintf(s->data + s->len, (size_t)n + 1, fmt, ap2);
        ok = true;
    }
}

vsnprintf never writes more than the size it is given. It always returns how many characters the full output needs. The function formats straight into the spare capacity first. Most calls fit, and they are done after one pass. Only when the output does not fit does it grow the buffer and format a second time. An earlier version always measured first with a null buffer, then grew, then wrote. It formatted every call twice and was 46% slower.

The failed attempt is not harmless. It wrote a truncated result over the terminator at data[len]. Restoring that byte keeps the promise that a failed call leaves the string unchanged. The out-of-memory test only caught a missing restore after it gained a starting state with some spare room, but not enough.

A va_list can only be walked once. The first vsnprintf consumes ap. va_copy makes a second, independent cursor before that happens. Both need va_end.

__attribute__((format(printf, 2, 3))) on the declaration tells GCC and clang that argument 2 is a printf format and the arguments start at 3. The compiler then checks every call site, exactly as it does for printf. Try str_appendf(&s, "%d", "text") and read the warning.

Prototypes, static, and headers

/* University */
int main() { ... }
void helper() { ... }

/* This repo */
int main(void) { ... }
static bool str_grow_(Str *s, size_t needed) { ... }

Before C23, int f() meant "takes unspecified arguments". The compiler would accept f(1, 2, 3) without complaint. In C23 it finally means "takes no arguments". (void) means the same in every standard and is still the clearest spelling. -Wstrict-prototypes flags the old form.

static on a function gives it internal linkage. It is invisible outside its translation unit. str_grow_ is an implementation detail, so it is static. The trailing underscore is this repo's convention for internal names. -Wmissing-prototypes catches a function that is neither static nor declared in a header. That is usually one you forgot to hide.

src/str/str.h uses #pragma once. tests/test.h uses classic #ifndef TEST_H guards. They do the same job. #pragma once is not in the standard, but every compiler you will meet supports it. Pick one per project. This repo has both, and making them consistent is a fine first commit.

Macros that behave

tests/test.h is a small catalogue of macro technique.

do { } while (0)
Turns a multi-statement macro into one statement. REQUIRE and RUN use it. Without it, if (x) REQUIRE(a); else ... breaks. With bare braces, the semicolon after the macro ends the if, and the else has nothing to attach to.
#cond
Stringification. The # operator turns the macro argument's source text into a string literal. That is how a failing check prints the expression you wrote.
__FILE__, __LINE__
Expand at the call site, not at the definition. Every failure reports the line of the CHECK that failed.
Thin macro, real function
CHECK_EQ_INT(a, b) only forwards to test_eq_int_, adding #a, #b, __FILE__ and __LINE__. Those are the only things a function cannot capture. A function evaluates each argument exactly once. A macro that used (a) twice would run a's side effects twice.
Redirecting a library call
#define realloc test_realloc_ after <stdlib.h> renames every later call. The header is already included, so its declaration of the real realloc is untouched.
Parenthesised parameters
(s).len in STR_FMT. Without the parentheses, STR_FMT(*p) would parse as *(p.len).

The unity build

/* University: separate compilation */
gcc -c str.c -o str.o
gcc -c main.c -o main.o
gcc str.o main.o -o main

/* This repo: main.c */
#include "str/str.c"

main.c includes the .c files directly. The whole program is one translation unit, compiled by one compiler invocation. The Makefile calls this a unity build.

The benefits are real. There is nothing to link. A full rebuild is a single fast command. The optimiser sees every function at once, so it can inline across what would have been file boundaries without LTO.

The costs are real too. Every static name shares one namespace, so two files cannot both have a static helper with the same name. Any change rebuilds everything. That stops mattering once the project is large enough to want parallel builds. Separate compilation is still the norm for large projects. The unity build is a deliberate choice for small ones.

The compiler as a reviewer

University builds usually run gcc main.c or gcc -Wall. This repo turns on about twenty warnings. Debug builds link two runtime checkers. The idea is that the compiler finds bugs before you do.

FlagWhat it catches
-Wconversion, -Wsign-conversionImplicit narrowing, such as size_t to int, or a negative int becoming a huge size_t. This is why the code casts explicitly, as in (size_t)n.
-WshadowAn inner variable hiding an outer one with the same name.
-Wformat=2printf format strings that do not match their arguments, and non-literal format strings.
-Wwrite-stringsTreats string literals as const char[], so char *p = "x" warns.
-WvlaVariable-length arrays. A VLA sized from input can overflow the stack.
-fsanitize=addressOut-of-bounds access, use after free, double free, leaks. It runs at runtime in debug builds.
-fsanitize=undefinedSigned overflow, misaligned access, bad shifts, null dereference. Also runtime.
-Werror (release only)Turns every warning into an error, so a release build cannot ship with one.

The sanitizers are the biggest change from university C. A bug that would corrupt memory silently now stops the program with a stack trace naming the line. Exercise 4 shows what that looks like.

-MMD -MP make the compiler write a .d file listing every header a source file included. The Makefile includes those files. Editing src/str/str.h therefore rebuilds what depends on it, without anyone maintaining that list by hand.

Testing beyond the happy path

University tests usually call each function once with a normal input and check the output. That leaves the code most likely to be wrong untested: the error paths. tests/test_str.c goes after them in three ways.

Injected allocation failure
tests/test.h wraps the allocator. test_fail_alloc_after(k) lets k allocations succeed and fails the rest. check_unchanged_on_oom fails the first allocation, then the second, and so on, and checks after every failure that the string is byte-for-byte unchanged. That is how the header's "on failure the string is left unchanged" promise gets tested.
Leak counting
The same wrappers count live allocations. RUN fails any test that ends with more than it started with. AddressSanitizer's leak checker is not available on macOS, so this is the leak check you get there.
A model
matches_model_under_random_ops applies 20,000 random operations to a Str and to a plain char array. It compares them after every step. The array is too simple to be wrong, so any difference is a bug in Str. The random generator is seeded, so a failure reproduces exactly.

A suite earns trust by failing when the code is wrong. Six bugs were planted in src/str/str.c one at a time to check that it does: realloc straight into s->data, a missing alias fix, a missing terminator, a free that forgets the buffer, an equality check that ignores length, and an unchecked addition. The suite caught all six. Try planting your own.

Run one test by name with make test T=self_append. A TEST you forget to RUN is an unused static function, so -Wunused-function warns about it.

Doc comments

Public declarations in src/str/str.h carry Doxygen comments. A comment that starts with /** is a doc comment. /* is an ordinary comment that Doxygen ignores.

/** Append @p v. @p v may point into @p s itself. */
[[nodiscard]] bool str_append(Str *s, StrView v);

typedef struct Str {
    size_t len;       /**< Bytes of content, excluding the terminator. */
} Str;
/** ... */
Documents the declaration that follows. The first sentence becomes the one-line summary.
/**< ... */
Documents the member to its left. Use it for struct fields.
@p name
Renders a parameter name in code font.
@param, @return
Full parameter and return sections. Use them when a one-line summary cannot say it all.
@file
Required at the top of a header. Without it, Doxygen does not document the free functions in that file.
@snippet{trimleft} test_str.c name
Pastes the lines between two /* [name] */ markers in tests/test_str.c. trimleft strips the indentation the test body adds.

The examples in the reference are snippets of the tests rather than @code blocks typed into the header. A typed example rots silently when the API changes. A snippet is compiled and run by make test. If someone renames a marker, make docs fails.

Run make docs and open build/docs/html/index.html. The build fails if any public declaration lacks a doc comment, so the reference cannot fall behind the header. clangd shows the same comments when you hover with K in Neovim.

Exercises

Each exercise is small and lands in this repo. Run make test after each one.

  • Make SV reject pointers. Change the macro body to .data = "" lit "". Adjacent string literals are concatenated, so a literal still works. A pointer is a syntax error. Confirm that SV(p) no longer compiles.
  • Add sv_find. Return the index of a byte in a StrView, or SIZE_MAX if it is absent. Use memchr. Document it with a doc comment and add a TEST for found, missing, and empty cases.
  • Add sv_trim. Return a view without leading and trailing whitespace. It allocates nothing, so it returns StrView rather than bool. Mark it [[nodiscard]] anyway. Calling it and dropping the result is always a bug.
  • Meet AddressSanitizer. In main.c, take StrView v = str_view(&s);, then append enough bytes to force a realloc, then print v. Run make run and read the report. Find the three stack traces: the bad read, the free, and the original allocation.
  • Replace __attribute__. Switch str_appendf to [[nodiscard, gnu::format(printf, 2, 3)]]. Check the format warning still fires. Then delete the three preprocessor lines under "Hide GNU attributes" in Doxyfile and check make docs still passes.
  • Turn the minimum capacity into a constexpr. Replace the literal 15 in str_grow_. Add a static_assert that it is at least 1.
  • Pick one header guard style. Make tests/test.h and src/str/str.h agree.
  • Write str_insert. Insert a StrView at an index. Keep the strong guarantee: on failure the string is unchanged. Handle a view that points into the string itself. This one combines growth, aliasing and memmove.

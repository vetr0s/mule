Str and StrView in practice

2026-11-07muleGuide

Str owns its bytes and can grow. StrView borrows bytes that something else owns and never allocates. The working pattern is to put text into a Str once, then pass StrViews around to read it, search it and cut it. Copy a view into a new Str only when the bytes must outlive the owner. Every example below is a file in docs/guide/str-examples/. Each output block is the real output of running that file.

Running the examples

Run these from the repository root. The examples read data/pg2554.txt, which is the Project Gutenberg text of Crime and Punishment. Run ./build data once to download it. Each file defines MULE_IMPLEMENTATION and includes dist/mule.h, the same way a project uses the library, so a single compiler call builds it.

mkdir -p .build && cc -std=c11 -Idist -fsanitize=address,undefined -g \
   docs/guide/str-examples/01_build.c -o .build/ex && .build/ex

Keep the sanitizer flag on while you learn. It turns most memory mistakes into a report, and -g makes that report name the line. The mistakes section shows two of those reports.

The two types

Both types hold a pointer and a length. The difference is ownership. A Str is responsible for its heap buffer, so it must be freed. A StrView points at bytes that belong to someone else, so it is never freed. It is only valid while the owner is alive and has not moved its buffer.

Str text     data ──► C r i m e   a n d   P u n i s h m e n t \0 · · · · · · ·
             len 20, capacity 30            spare capacity ──────────┘
                      ▲                 ▲
StrView word     data ┘ len 5           │       word  = "Crime"
StrView tail                       data ┘ len 10   tail = "Punishment"

The views above cost nothing to make. They are two machine words each. Slicing text a thousand times allocates nothing.

Str on its own

Build, read, free

A zeroed Str is a valid empty string that owns nothing. The first append allocates. Every call that might allocate returns bool, and a failed call leaves the string as it was. That makes it safe to chain calls with &&: the chain stops at the first failure and nothing after it runs.

{{code:01_build.c}} 
Rodion Raskolnikov, former student, age 23
len 42, capacity 60
Rodion Raskolnikov, former student, age 23

Two ways to print are shown. STR_FMT passes the length and the pointer to %.*s, so printf prints exactly len bytes. It works on a Str and on a StrView. str_cstr returns a NUL-terminated pointer for APIs like puts and fopen. It never returns null, even for an empty string.

The capacity is 60 because the buffer starts at 15 bytes and doubles when full: 15, 30, 60. Doubling means appending one byte at a time still costs a constant amount per byte on average.

Reuse one buffer

str_clear sets the length to zero and keeps the allocation. In a loop that builds a string per item, clear and refill one Str instead of creating and freeing one per pass.

{{code:02_reuse.c}} 
PART 1   capacity 15, data 0x6020000000f0
PART 2   capacity 15, data 0x6020000000f0
PART 3   capacity 15, data 0x6020000000f0

The address is the same on every pass. One allocation served all three strings.

Read a whole file

str_append_file reads until end of file. If s is empty it takes the read buffer over instead of copying it. On failure it leaves s unchanged, and ferror tells you whether the read failed or memory ran out. Check ferror before fclose, because the stream is gone after.

StrView on its own

A view needs bytes that already exist. There are four ways to get one:

SV("text")
A string literal. The length is computed at compile time. Use it only on a literal, never on a pointer.
sv_from_cstr(p)
A NUL-terminated char * from a C API, such as argv[i] or getenv. It measures with strlen. Null gives an empty view.
str_view(&s)
The whole contents of a Str.
sv_slice(v, from, to)
Bytes from up to but not including to of another view. It asserts the range is inside v.

Inspect and slice

This parses a header line in the format Gutenberg uses. Trimming, finding and slicing all return new views into the same literal. Nothing is copied.

The third line shows the bug on purpose. key is five bytes long, but %s ignores the length and prints until it finds a NUL. Here that printed the rest of the line, including the \r\n. On a view with no NUL after it, the same mistake reads past the buffer. Always print a view with %.*s and STR_FMT.

The find functions return SV_NPOS when there is no match. Always compare against it before you use the index.

sv_token_next is strtok without its problems. It does not write NULs into your text. It keeps no hidden state, so two loops can run at once.

Using them together

One owner, many views

This is the shape most text processing takes. One Str holds the whole file. Every line, word and match is a view into it. The program makes one allocation for the file and none for the 22,750 lines.

{{code:07_lines.c}} 
Author: Fyodor Dostoyevsky
22750 lines, 78 chapters, 784 mentions of Raskolnikov

Two details matter. The file has Windows line endings, so each line split on "\n" still ends in \r. sv_trim removes it along with any other surrounding whitespace. Second, nothing writes to text while the loop runs. That is what keeps every view valid. The count of 784 agrees with grep -o Raskolnikov data/pg2554.txt | wc -l.

Copy when it must outlive the source

A view dies with its owner. When you need a piece of text after the owner is freed, copy it into a Str of its own. Here a struct keeps the title and author while the 1.2 MB file buffer is released.

{{code:08_keep.c}} 
Crime and Punishment by Fyodor Dostoyevsky

A struct that holds Str fields owns them. Give it a matching _free function that frees each field, like book_free. Zero-initialise the struct with = { 0 } so the free function is safe to call even if parsing stopped part way.

Writing your own functions

The library's own signatures are the pattern to copy. A function that only reads text takes a StrView. A function that produces text takes a Str * to append to and returns bool. The caller then decides where the output goes and whether to clear it first.

{{code:09_replace.c}} 
Raskolnikov went out. Raskolnikov came back.

Taking a StrView makes a function accept every kind of string. A caller with a literal passes SV("..."). A caller with a Str passes str_view(&s). A caller with a char * passes sv_from_cstr(p). One function serves all three.

The last call in the example appends a string to itself. That is safe. str_append notices that the view points into its own buffer and recomputes the address after growing.

Mistakes and what they look like

A view kept across a reallocation

This is the mistake to understand first. Any call that may grow a Str can move its buffer, and every view into the old buffer then points at freed memory.

{{code:10_dangling.c}} 
ERROR: AddressSanitizer: heap-use-after-free on address 0x6020000000f0
READ of size 1 at 0x6020000000f0 thread T0
    #5 in main 10_dangling.c:16

    #0 in realloc
    #1 in mem_realloc mule.h:1996

The report is trimmed to the useful frames. Read it bottom up. Line 10 allocated the buffer. Line 14 grew it, and mem_realloc freed the old one. Line 16 read through the stale view. There are two fixes. Take the view after the last call that grows the string. Or call str_reserve for the full size first, so the appends fit and the buffer never moves.

Copying a Str struct

Str b = a; copies the pointer, not the bytes. Now two structs think they own one buffer, and freeing both is a double free.

{{code:11_double_free.c}} 
ERROR: AddressSanitizer: attempting double-free on 0x6020000000f0 in thread T0:
    #1 in mem_realloc mule.h:1982
    #2 in str_free mule.h:2152
    #3 in main 11_double_free.c:12
freed by thread T0 here:
    #1 in mem_realloc mule.h:1982
    #2 in str_free mule.h:2152
    #3 in main 11_double_free.c:11

To duplicate a string, make a real copy with str_from(&b, str_view(&a)). To hand ownership over, write Str b = str_take(&a);. It moves the buffer to b and leaves a empty, so only one owner remains. Pass a Str to functions as Str * so this never happens by accident.

Exercises

Each one starts from an example file. Keep the sanitizer on and check the output against what you expect.

  • Fix 10_dangling.c both ways: once by moving str_view below the append, once with str_reserve. Confirm the sanitizer stays quiet.
  • Extend 08_keep.c so Book also keeps the Release date: line. Remember the new field in book_free.
  • Count every word in the novel with sv_token_next in 07_lines.c. Decide which bytes count as delimiters.
  • Write bool join(Str *out, const StrView *parts, size_t n, StrView sep) and use it to print the sorted names from 06_sort.c as one comma-separated line.
  • Write StrView path_basename(StrView path) that returns everything after the last /. It returns a view, so it cannot fail. Test it on "", "a", "a/" and "/usr/lib/libc.so".

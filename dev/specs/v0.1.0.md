# MULE v0.1.0

## Goal
Cut the 0.1.0 release. Map is a new module since 0.0.1, so the minor bump is due. Two open TODO items finish modules that already ship: `map_remove` completes Map, and `str_take` completes the move story that the str guide works around by hand. Nothing opens a new module. The commit leaves `dist/mule.h` regenerated and the version macros at 0.1.0. Tagging and pushing are the user's job after the commit.

## Acceptance criteria
1. `map_remove(m, key)` on a map that holds `key` returns true. Afterwards `map_find` of that key is false, `m.len` is one lower, and every other key is still found with its value intact.
2. `map_remove(m, key)` on a map that lacks `key`, or on a zero-initialised map, returns false and changes nothing.
3. Removing an entry that is not last moves the last entry into its place. Removing the last entry moves nothing. `data` stays dense, so a loop over `0..len` visits every remaining entry exactly once.
4. After any sequence of puts, removes and clears, the map matches a reference model. This includes keys that collide, so backward-shift deletion keeps every probe chain intact.
5. `map_remove` never allocates, so it needs no OOM-unchanged case. A test proves it runs with `test_fail_alloc_after(0)` armed and still succeeds.
6. `map_remove` works on a map backed by an arena.
7. `str_take(&a)` returns a `Str` with the old data, len, capacity and alloc of `a`. `a` is then empty with no memory, and keeps its `alloc`. Freeing the result frees the original buffer exactly once, with no leak and no double free.
8. `str_take` on a zero-initialised `Str` returns an empty `Str` and leaves the source zero.
9. `str_take` does not allocate and cannot fail, so no OOM-unchanged entry applies.
10. `MULE_VERSION_MAJOR`, `MINOR`, `PATCH` and `MULE_VERSION` are 0, 1, 0 and "0.1.0". `make version` prints `0.1.0`, and `tests/test_dist.c` agrees.
11. `CHANGELOG.md` has an empty `## [Unreleased]` above `## [0.1.0] - 2026-11-07`. The 0.1.0 section lists `map` (existing line), `map_remove` and `str_take` under Added. The footer links are `[Unreleased]: .../compare/v0.1.0...HEAD`, `[0.1.0]: .../compare/v0.0.1...v0.1.0` and the unchanged `[0.0.1]` link.
12. `TODO.md` checks off `map_remove` and `str_take`. The deferred items stay unchecked.
13. `dist/mule.h` is regenerated by `make dist` and contains both new functions and version 0.1.0.
14. `make test`, `make release` and `make docs` pass. Every file in `notes/str-examples/` compiles with `cc -std=c11 -Isrc`.
15. `notes/str-and-strview.html` is regenerated and no longer tells readers to write `a = (Str){ 0 };` to hand over ownership.

## Test plan
1. `tests/test_map.c`, `remove_deletes_key`: put five keys, remove one, assert it returns true, `map_find` is false for it, `len` is 4, and the other four still find with their values.
2. `tests/test_map.c`, `remove_missing_key`: remove an absent key from a filled map and from `WordMap m = { 0 }`. Assert false, and `len`, `data`, `slots` and the entries are unchanged.
3. `tests/test_map.c`, `remove_swaps_last_into_hole`: remove the first of three entries and assert `data[0]` is the old last key with its value, and `len` is 2. Remove the last entry and assert the others did not move.
4. `tests/test_map.c`, `matches_model_under_random_ops` and `matches_model_in_arena`: add remove to the random op mix. Assert find and `len` agree with the model after each step. A second case, `remove_with_colliding_keys`, uses `many_key` runs large enough to force probe chains, removes from the middle, and finds every survivor.
5. `tests/test_map.c`, `remove_does_not_allocate`: fill a map, arm `test_fail_alloc_after(0)`, assert `map_remove` returns true, disarm. The harness leak check covers the rest.
6. `tests/test_map.c`, `remove_in_arena`: build the map on an arena allocator, remove some keys, assert finds, free the arena.
7. `tests/test_str.c`, `take_moves_ownership`: build a `Str`, take it, assert the result has the old pointer and content and the source is empty with `data == NULL` and the same `alloc`. `str_free` the result. The harness fails on a leak, and ASan on a double free.
8. `tests/test_str.c`, `take_zero_str`: take from `Str s = { 0 }`. Assert both are empty.
9. `tests/test_str.c`, `take_keeps_allocator`: take from a `Str` on an arena. Assert the result and the source both have the arena as `alloc`. This covers the no-allocation claim, because the test arms `test_fail_alloc_after(0)` around the call.
10. `tests/test_dist.c`, existing version check: passes with the new macros. Run `make version` and assert it prints `0.1.0`.
11. Manual check: read the changelog section and footer links. No test.
12. Manual check: read the TODO boxes. No test.
13. `tests/test_dist.c` compiles against the regenerated `dist/mule.h`. Run `grep -c 'map_remove_\|str_take' dist/mule.h` and expect a non-zero count. Run `make dist` twice and `git diff --exit-code dist/mule.h` the second time.
14. Run `make test`, `make release`, `make docs`, and `for f in notes/str-examples/*.c; do cc -std=c11 -Isrc -fsyntax-only $f; done`. Doxygen fails on an undocumented `map_remove` or `str_take`, which covers the doc rule.
15. Run `python3 tools/gen-guide.py` and `grep -c 'a = (Str){ 0 }' notes/str-and-strview.html`. Expect 0.

Watch `remove_deletes_key`, `remove_swaps_last_into_hole` and `take_moves_ownership` fail once against a stub that returns false or does nothing, before trusting them.

## Out of scope
Deferred items, one line each.
- Map seed: only matters for untrusted keys, and no caller has them.
- `map_remove` by index: by key is the narrower reading, and a caller holding an index can read the key from `data`.
- Order-preserving remove: it needs a shift and an index rebuild, and the TODO chose swap-with-last.
- Arena save and restore marks: touches the allocator contract, and no caller needs it.
- Failing `Allocator` for `src/test/test.h`: internal harness cleanup with no user-visible change.
- `sv_parse_u64` and other bases: TODO says only when a caller needs them.
- `sv_find_last`, `sv_trim_left`, `sv_trim_right`, `sv_eq_ignore_case`: TODO says only when a caller needs them.
- `notes/str-examples` moving to `dist/mule.h`: a doc change that suits a later patch release.
- Wall-clock ISO timestamps in `time`, and logger timestamps: new surface in two modules.
- Files and paths module: a new module.
- Argument parser module: a new module.
- MSVC support: conflicts with the Unix-only target.
- Per-thread log buffer: no profile shows the need.
- Fuzzing: needs Linux and libFuzzer.
- UTF-8, in-place `Str` edits, threads, INI or JSON, process capture: listed under Later.
- Tagging, pushing and the Release workflow: the user does these after the commit.
- Changing `str_free`, or making `str_take` reset `alloc`: the narrower reading keeps `alloc`, as `str_free` does.

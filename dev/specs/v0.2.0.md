# MULE v0.2.0

## Goal
Ship the four items TODO.md listed as patches on 0.1.0, as additions. The review found the harness change breaks `MULE_TEST` users, so this shipped as 0.2.0. `sv_parse_u64` parses unsigned integers in bases 2 to 36, so the future `args` module can read `-j 8`. Arena marks let a function free just what it allocated. The test harness stops redefining `malloc` and installs a counting, failing `Allocator` instead. The str examples and guide include `dist/mule.h`, which is how readers use the library. The change bumps no version and cuts no release.

## Acceptance criteria
Item 1, parsing.
1. `sv_parse_u64(SV("8"), 10, &n)` returns true with `n == 8`. `"18446744073709551615"` in base 10 parses to `UINT64_MAX`.
2. Base 16 parses `"ff"`, `"FF"` and `"Ff"` to 255. Base 2 parses `"101"` to 5. Base 36 parses `"z"` to 35. Base 8 rejects `"8"`.
3. Each of these returns false and leaves `n` unchanged. The empty view. A leading `+` or `-`. Leading or trailing whitespace. A trailing byte that is not a digit of the base. A `0x` or `0b` prefix. A value above `UINT64_MAX`, such as `"18446744073709551616"`.
4. For random digit strings in bases 2 to 36, the result and the success flag agree with `strtoull` run on the same text, once the cases `strtoull` accepts and this function rejects (sign, whitespace, prefix, empty) are filtered out.
5. `sv_parse_i64` keeps its signature and behaviour. Its existing tests pass unchanged.
6. A base below 2 or above 36 trips an assert. The header documents it under `@pre`.

Item 2, arena marks.
7. `Arena a = { 0 }; ArenaMark m = arena_mark(&a);` gives a mark of an empty arena. After allocating, `arena_restore(&a, m)` frees every block, leaves `a.head == NULL` and `a.last == NULL`, and keeps `a.allocator`. The arena is still usable and still frees cleanly with `arena_free`.
8. A mark taken inside one block, then more allocations in the same block, then restore: `a.head` is unchanged and the next `arena_alloc` of the same size and alignment returns the same address that the first post-mark allocation got.
9. A mark taken, then allocations that add new blocks, then restore: every block added after the mark is freed, the mark's block is the head again, its `used` is as at the mark, and the harness reports no leak.
10. Allocations made before the mark keep their contents after restore.
11. An allocation made before the mark does not grow in place after the mark. Taking a mark clears `last`, so growing the previous newest allocation through the arena's `Allocator` moves it. Restore therefore cannot cut off a buffer that grew past the mark.
12. Nested marks restore in last-in first-out order: restore the inner mark, then the outer, and the arena ends as at the outer mark.
13. `arena_reset` and `arena_free` still behave as before. A mark taken before either is dead afterwards. The header says so.
14. A `Str` on `arena_allocator(&a)` that is built after a mark and then dropped by `arena_restore` leaves the arena allocating the same addresses again.

Item 3, harness allocator.
15. `src/test/test.h` contains no `#define malloc`, `calloc`, `realloc` or `free`. `grep -n '#define \(malloc\|calloc\|realloc\|free\)' src/test/test.h` prints nothing.
16. `mem_set_heap(&alloc)` makes `mem_realloc(NULL, ...)` call `alloc`, and `mem_set_heap(NULL)` restores libc. It returns the previous setting. `arena_alloc` takes its blocks and `arena_free`, `arena_reset` and `arena_restore` release them through `mem_realloc(NULL, ...)`, so they go through the installed heap too. With no heap installed, behaviour is as before.
17. `test_init` installs the harness `Allocator`. `RUN` still fails a test that ends with more live allocations than it started with. A test that leaks one `Str` fails, and a test that frees it passes.
18. `test_fail_alloc_after(n)` keeps its signature and meaning. It makes allocation fail for null-allocator code in Str, Arr, Map and log, and for the arena's block allocation. Every test that used it passes unchanged, including `arena_oom_leaves_state` and `check_unchanged_on_oom`.
19. `tests/test_dist.c` `hooks_reach_the_library` passes through `dist/mule.h` with no macro redefinition.
20. `heap_growth_returns_memory` still measures libc growth. It uninstalls the harness heap for its run and restores it afterwards.
21. The test module comment in `src/test/test.h` and the lines in `AGENTS.md` that describe the malloc redirection describe the installed `Allocator`.

Item 4, examples on `dist/mule.h`.

## Out of scope
- Changing `sv_parse_i64`: a new signature would break callers and force a minor bump. A base-aware signed parser waits for a caller.
- Prefix handling and base 0 auto-detect in `sv_parse_u64`: callers pass the base they mean. A prefix is one more way to disagree with the caller.
- Whitespace trimming in the parsers: the module rule is that partial matches fail.
- Mark validation: a stale or out-of-order mark is undefined, as a freed pointer is. A generation counter costs a field on every arena.
- Per-thread or per-allocator heap hooks: `mem_set_heap` is one process-wide setting, not thread safe, and meant for the harness.
- Marks for allocators other than `Arena`.
- Passing a `Allocator` explicitly to every OOM test: the hook keeps all current tests unchanged, and the leak check keeps covering null-allocator code.
- A `make examples` run of the programs: compiling is enough. The guide output is captured by hand as before.
- Moving the benchmarks or `main.c` to `dist/mule.h`: they stay on `src/`.
- Version bump, release, tag and push: the user calls releases.
- The build-in-C items: `args`, the build script and anything else in TODO.md.

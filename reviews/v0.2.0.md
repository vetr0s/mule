# Review: v0.2.0

Read: all of the diff against HEAD plus specs/v0.2.0.md. Nothing was run. The orchestrator's clang results are taken as given. gcc was judged by reading.

## Bugs

1. Medium. tests/test_mem.c:64 and :74. `heap_growth_returns_memory` calls `REQUIRE(q != NULL)` after `mem_set_heap(NULL)` and restores the harness at line 74. If the grow fails, REQUIRE returns early, the harness heap stays uninstalled, and every later test runs on bare libc. Leak counting and `test_fail_alloc_after` go silent, so `arena_oom_leaves_state` and the like fail with confusing errors. Fix: restore before the REQUIRE, or break out of the loop and restore once. Found by reading.

2. Medium. tests/test_mem.c:397 to :417. `heap_hook_routes_null_allocator` installs a heap whose ctx is the stack variable `c`. Each `REQUIRE` between 397 and 411 returns without calling `mem_set_heap(prev)`. The next test then calls `counting_heap_fn` with a dangling `ctx`, which is undefined behaviour. It only bites when the test is already failing, but it turns one failure into a crash in an unrelated test. Found by reading.

No bug found in: `arena_mark`, `arena_restore`, `mem_free_blocks_`, `sv_parse_u64`, or `test_heap_fn_`. Checked and fine:
- A zero mark frees every block.
- `last` is cleared on both mark and restore.
- The block size passed to the free (`sizeof(ArenaBlock) + cap`) equals the allocation size.
- `arena_alloc` only bumps the head, so no allocation lands in an older block.
- A mark taken with a full head block restores correctly.
- `test_heap_fn_` counts correctly. Realloc never double-counts, a failed realloc leaves the count alone, a free of null is not counted, and the budget is spent only on non-free calls.
- In `sv_parse_u64`, `out` is written only on success, the digit mapping is right, and the assert is on base.
- gcc: no `MULE_NODISCARD` result is cast away. `mem_free_blocks_` assigns the result, and `moving_realloc` assigns it too. `old` is read earlier in `moving_realloc`, so there is no set-but-unused warning.

The harness heap was not seen freeing a block from another heap. `test_init` installs it before any arena exists. The only switch is `heap_growth_returns_memory`, which allocates and frees every block inside the window.

## Spec gaps

1. Low to medium (semver, a decision for the user). src/test/test.h:86 to :105, with CHANGELOG.md:21 to 23. The harness no longer redefines `malloc` and `free`. test.h ships in dist/mule.h under `MULE_TEST`. Two things change for a project's own test code:
   - A direct `malloc` that leaks used to fail the test. It now passes.
   - A direct `free(s.data)` of library memory used to decrement the count. It now leaves the count raised, so a correct test fails with a false leak.
   AGENTS.md calls changed behaviour a caller relies on a break. While major is 0 that bumps the minor. The spec says no bump.
   - The change is on the user's roadmap, and 0.2.0 is planned, so the next release is a minor bump anyway.
   - The CHANGELOG entry sits under Changed, with no mark that it breaks anything.
   - Recommendation: keep the version as is. Reword the entry as a breaking change for `MULE_TEST` users and say what to do: allocate through `mem_realloc` or an `Allocator`, and do not free library memory with `free`. The next release should be a minor bump.

2. Low. src/mem/mem.h:14 and AGENTS.md:40. "Only this module calls malloc, realloc and free" and "Only `src/mem/` calls libc allocation directly" are false. src/test/test.h:95 and :97 call `free` and `realloc`, and tests/test_mem.c does too (`counting_heap_fn`). This predates the change, because the old wrappers also called libc. The spec says the sentence "stays true". Reword both to "outside the test harness", or the next reader trusts a false rule.

3. Low. AGENTS.md:150 to 160 and the Makefile. `make test SANITIZE=` run literally in an existing `build/` reuses the ASan binaries. The rule at Makefile:96 has no prerequisite on the flags, so the run skips `heap_growth_returns_memory` and still reports pass. Spec criterion 31 and AGENTS.md give that literal form. CI avoids this with `BUILD=build/nosan`. It is worth one line: "use `BUILD=build/nosan` with `SANITIZE=`". Found by reading and not run.

4. Low. docs/concepts.md Threads paragraph. The edited line runs past 80 columns ("Set them before starting threads. Each log line is written with one"). The wording is accurate. This is a reflow only.

## Missing tests

1. Medium. tests/test_mem.c:28 and src/mem/mem.c:34 to :47. The libc branch of `mem_realloc` is no longer covered in the default build. `heap_realloc_and_free` and every other test now go through the harness heap. The only test that reaches libc is `heap_growth_returns_memory`, which is Apple-only and not under ASan, plus the alloc and free tail of `heap_hook_routes_null_allocator`. Under ASan builds and on Linux, nothing covers libc grow, libc shrink, or `realloc(p, 0)` through `mem_realloc`. That includes the Apple malloc-and-copy branch and its `if (p == NULL) return NULL;` OOM return. That return used to be hit by the old `malloc` macro under `test_fail_alloc_after`, so it was covered. A broken libc path would pass CI. This is a finding. Fix: run `heap_realloc_and_free` with `mem_set_heap(NULL)`, restoring before any REQUIRE. Cover the Apple OOM return with a heap or allocator that fails `malloc`, or accept it as untestable and say so.

2. Low. tests/test_str.c:844 `parse_u64_matches_strtoull`. It reaches the overflow branch in every base. Uniform lengths of 1 to 70 give 65 or more digits in about 7% of base-2 cases, and leading zeros cut that further. Base 2 sees few overflow hits, and exact `UINT64_MAX` is only tested in base 10. I did not run a count. Optional: add `UINT64_MAX` and `UINT64_MAX + 1` for bases 2 and 16 to `parse_u64_bases` or `parse_u64_edges`. The `10000000000000000` hex reject already covers base 16 overflow.

3. None for the marks. Plan items 7 to 14 each have a test.
   - `mark_stops_in_place_growth` checks both the unmarked and marked cases.
   - `restore_drops_scoped_str` assumes a 600-byte Str stays inside one block, which holds while `MEM_ARENA_BLOCK` is at least 1 KiB.
   - There is no test for the zero mark used on a non-empty arena, which frees everything. The header says the zero value is the mark of an empty arena, so this is documented behaviour.
